Squizzumables Changelog Archive
==============================

Shipped versions before the current one. The packager reads changelog.txt
verbatim (see manual-changelog in .pkgmeta), so that file holds only the
version being built -- otherwise every CurseForge release reposts the whole
history as its release notes. Older sections move here instead of being
deleted: many carry root-cause writeups worth grepping before assuming a bug
is fresh. This file is in the .pkgmeta ignore list, so it never ships.

V1.69

- Fixed the Earth Shield reminder nagging Shamans who were effectively solo. A delve
  companion or a follower dungeon's NPCs fill your party, so the reminder counted that as
  being in a group and asked you to place a second Earth Shield on someone who cannot take
  one. It now requires a real player in the group, the same test the Coach's Whistle
  reminder already used
- Fixed the Earth Shield reminder guessing at Elemental Orbit instead of checking whether
  you have the talent. It assumed that a shield on yourself meant you had Elemental Orbit,
  which was wrong both ways round: shielding yourself without the talent left the reminder
  up permanently, and having the talent with your only shield on someone else meant it
  never reminded you to shield yourself. It now reads the talent, matching what the Earth
  Shield buttons have always done
- Fixed a Cooldown Manager crash that could fire in combat. Reading a buff's duration or
  stack count directly throws an error when the game hides aura data, which it does in
  combat, raids, Mythic+ and PvP -- exactly when the icons are being updated. The reads now
  go through the same safe path the rest of the addon uses, and an unreadable buff falls
  back to showing the spell's cooldown instead of erroring
- Cooldown Manager groups can now be styled. Border thickness and colour (or your class
  colour), how much of the icon art is cropped, and an optional coloured background behind
  each icon. All of it is per group, so one group can be a chunky class-coloured row and
  another a small plain one. The border was previously a fixed 1px black line you could
  only switch on or off, and the icon crop was not adjustable at all
- The icon background pairs with Hide Until Active: the group keeps a visible footprint
  while its icons are hidden, so you can still see where it is
- Essential, Utility and Buffs now exist as standard groups and fill themselves, mirroring
  Blizzard's own Cooldown Manager categories. Previously every group was one you had to
  make yourself and a spell showed nothing at all until you had assigned it by hand, so a
  fresh setup had nothing on screen and nothing to style. Buff and proc cooldowns are also
  picked up now; only Essential and Utility were before
- Anything you assign to a group of your own still goes there. The standard groups are only
  where a spell ends up when you have not said otherwise
- New per-group "Enable Group" tick, so a standard group you do not want can be switched
  off without unassigning anything
- Cooldown Manager groups have new visibility conditions: hide while mounted, only show in
  instances, hide in housing, hide without a target, and hide unless your target is an
  enemy. These sit alongside the existing Hide Out of Combat and Hide Until Active
- Groups can now be anchored to each other. Pick another group, a side and an offset, and
  this group follows it -- so a stack of bars is positioned by moving only the top one. An
  anchored group cannot be dragged, since it is placed by whatever it follows, and
  anchoring two groups to each other is ignored rather than allowed to break the layout
- Fixed a group set to Enable Group off reappearing as soon as combat ended. Two copies of
  the visibility logic existed and only one of them knew about that tick; there is now one
- Hide Until Active now closes the gaps. Hidden icons used to keep their slot, so the ones
  that were showing stayed scattered across the group with holes between them. Only the
  visible icons take a slot now, and the row re-packs as buffs come and go -- so with a
  Centered growth direction they grow out from the middle, which is what tracked buffs
  want. The three standard groups now default to Centered, matching Blizzard's own bars
- Fixed the Buffs group showing duplicates of your Essential and Utility abilities. The game
  lists an ability twice -- once for its cooldown and once for the buff it applies -- under
  a different ID each time, so nothing keyed on an ID could spot the pair. They are matched
  by name now, and the cooldown entry wins, since that is the one carrying cooldown data
- Tracked buffs now show Blizzard's own icons rather than copies of them, so their cooldown
  swipes, stack counts and timers keep working in combat. Copying them could never work:
  the game hides a buff's remaining time from addons in combat, refuses to hand it over even
  when asked for a specific aura, and hands out its icon frames on demand so there is no
  reliable moment to catch the value in passing. Using Blizzard's frames sidesteps all of
  it -- the game keeps drawing them, exactly as it does on its own bars
- Your layout settings still apply to them: growth direction, spacing, icons per row and
  icon size all work as before, and Hide Until Active now comes free because the game hides
  an inactive tracked buff itself. The per-icon border, zoom and background do not apply to
  buffs any more, since these are the game's own icons
- Round icons, a group background panel, and a charge-number toggle round out the Cooldown
  Manager styling. The group panel sits behind the whole row rather than each icon and
  grows and shrinks with it, including as a Hide Until Active group packs down
- The keybind, charge number and cooldown countdown can each be placed in any of nine
  positions on the icon, with their own offsets and text size. Cooldown text defaults to
  Centre, which leaves the game's own placement alone
- Cooldown Manager icons can now show their keybind. Per group, with a colour and text size,
  read from your action bars -- an ability that is not on a bar has no key to show. It
  deliberately does not follow bar swaps from stealth, druid forms or dragonriding: a
  keybind that rewrites itself every time you shapeshift is less use than a steady one, and
  a talent that replaces a spell is followed so the key still appears
- New "Always Show Buffs" option for the tracked buff group: keep a slot for every buff you
  track, showing a dimmed placeholder while it is not up, rather than the row shrinking to
  only the active ones. "Grey Out Inactive" and an opacity slider control how those look
- Fixed tracked buffs showing no duration swipe. A tracked buff's aura is frequently a
  different spell from the one its cooldown is listed under, and only that one was being
  checked -- so the lookup found nothing and fell back to a spell cooldown those entries do
  not have. All the spell IDs the game offers for a cooldown are checked now
- Fixed most Cooldown Manager icons never refreshing between reconciles. The update pass
  only recognised spells you had assigned to a group by hand, so everything relying on the
  new standard groups was skipped -- desaturation, hide-until-active and the icon artwork
  retry all stalled until something else forced a rebuild
- New "Hide Blizzard's Cooldown Manager" option, so only these icons show. Blizzard's bars
  are faded rather than hidden: the game stops updating a frame once it is hidden, and this
  addon reads live buff state from those frames, so hiding them outright would stop your
  own icons tracking buffs. Unticking brings them straight back, as does switching the
  Cooldown Manager off. Edit Mode re-applies its own opacity to those bars whenever it
  refreshes, which made them reappear a second after being faded, so the fade is now held
  in place rather than set once. The fade also lifts while Edit Mode is open, so Blizzard's
  bars stay visible and positionable there instead of leaving you an empty selection box
  where the icons should be. They are moved off screen as well as faded, because an
  invisible bar still catches the mouse and was showing Blizzard's cooldown tooltips over
  empty screen, and they are hidden the instant you log in rather than half a second later,
  which is what made them flash on screen at every reload
- Fixed Cooldown Manager groups set to Centered growth having their drag area in the wrong
  place. Icons were centred on the container's left edge instead of its middle, so the
  group's move handle sat down and to the right of the icons it belonged to -- dragging it
  moved icons that were nowhere near it, and clicking the icons did nothing. The four
  corner growth directions were never affected
- Cooldown Manager icons that had no artwork available when they were built now fill it in
  afterwards, instead of staying blank forever and leaving what looked like an empty group
- Every frame's green move box now says which frame it is while frames are unlocked. There
  can be a dozen or more on screen at once and they were impossible to tell apart
- Anchoring another addon to Blizzard's Essential Cooldowns (or Utility, or the buff bars)
  now works even with Hide Blizzard's Cooldown Manager on. Each hidden Blizzard bar is
  parked invisibly on top of the group that replaced it, matching its position and size, so
  it stays exactly where the icons are and an anchor pointed at it still lands correctly --
  it also follows when you drag the group. New "Keep Blizzard's frames on our groups" tick
  next to the hide option turns this off if you would rather they went off screen
- Other addons can also anchor to our own frames. Each group shows its frame name in the
  Cooldowns tab -- SQZ_CDMGroup_Essential and so on -- which is what to give an addon that
  anchors by frame name. From Lua there is also
  Squizzumables_GetCDMGroupFrame("Essential") and the same for "Utility", "Buffs" or any
  group you have made. The frames now last the whole session instead of being rebuilt when
  you change spec or switch the Cooldown Manager off and on, which used to leave anything
  anchored to them pointing at a dead frame
- The Cooldowns tab is now just the Cooldown Manager: the master switch and the three
  standard groups with their styling. Making your own groups and assigning individual
  spells has moved to a new Custom Icons tab, so the settings you are most likely to want
  are not buried under a group-creation form and a list of every spell you know

V1.68

- The Just For Kel alert image no longer swallows mouse clicks. It sits in the middle of
  the screen during Bloodlust, so anything it covered was unclickable for as long as it was
  up -- and since the image only appears mid-pull, that was the worst possible moment for it.
  It is now click-through at all times
- Drag it into place with Unlock Frames, the same as every other frame. The "Lock alert
  image position" checkbox has been removed: Unlock Frames always overrode it anyway, and
  with the image click-through there was nothing left for it to do
- Fixed the alert image becoming permanently undraggable after using "Lock all frames".
  Locking cleared its movable flag and nothing ever put it back, so Unlock Frames could show
  the image but not move it until you reloaded

V1.67

- Fixed Rite of Sanctification and Rite of Adjuration never showing a button for Protection
  Paladins. The Rites are a Lightsmith choice node, and Lightsmith is a Holy and Protection
  hero tree -- but the button was checking for Holy spec, so half the paladins who can take
  the talent could never see it. It now checks whether you actually know the spell, which is
  the only thing that ever mattered. The setting itself was always listed, which is why it
  looked switched on and did nothing
- Weapon oil buttons now correctly step aside for Protection Lightsmith Paladins too. A Rite
  occupies the same main-hand slot an oil would, so offering both was two buttons fighting
  over one slot. Holy already behaved this way
- Buff sounds no longer switch themselves off for the rest of the session when the game
  refuses to register them. Rebuilding the registrations clears the old ones first, so a
  refusal used to leave you with no buff sounds at all until you relogged -- reported from
  LFR, where combat, people leaving the group and the vote-kick popups all pile onto the
  same protected code path. A refused rebuild is now retried automatically

V1.66

- Fixed buff sounds not registering when the change happened during combat. Handing a sound to
  the game is a protected call and combat refuses it, so an alert added, edited or switched on
  mid-fight was dropped on the spot and stayed silent until you reloaded. Those registrations are
  now held and applied the moment you leave combat. Sounds you already had registered were never
  affected -- they kept playing throughout
- The callout buttons doing nothing in Mythic+, open since 1.64, turned out not to be this addon
  at all. Another addon had tainted the game's chat-send function, which blocks every addon's
  secure macro from sending chat on that client -- ours was just one casualty. Removing that addon
  fixed the callouts, with no change needed here. In the reported case it was GBankManager. If
  your callouts do nothing in a key, the error traceback names whichever addon is responsible

V1.65

- Reverted the callout button change from 1.64. That version changed how callout buttons send
  their message, which was meant to fix them not firing in Mythic+ for one player -- instead it
  broke them in Mythic+ for people they had been working for, including me. The old mechanism is
  back. If callouts worked for you before 1.64, they work again
- Say and Yell stay removed from callouts. That part of 1.64 was right for its own reasons: the
  game blocks addons from using those two inside instances, which is the only place callouts
  appear, so they could never have worked there
- The original report -- callout buttons doing nothing in a key -- is still open. It affects some
  setups and not others, and chasing it needs a log from a client where it actually happens


V1.64

- Fixed buff sounds silently switching themselves off when you opened the settings with a slash
  command. Registering a buff sound is a protected call, and the game blocks those when the chain
  starts at the chat box -- so typing /sq config cleared every registration and then could not put
  them back, leaving you with no buff sounds until your next login. Opening the panel any other
  way was unaffected, which is why it took a bug report to find. The registration now happens a
  moment later, out of that chain, where the game allows it
- Fixed dungeon callout buttons doing nothing when clicked in Mythic+. The buttons ran their
  message as a macro, and running a macro from a button is something the game only allows addons
  to do under conditions Mythic+ breaks -- so the button drew, moved and highlighted normally and
  then quietly did nothing, with no message and no error. Outside a key it worked, which is why it
  looked like it worked. They now send the message directly, the same way the feast announce
  always has, which the game is happy with anywhere including mid-pull
- Say and Yell are no longer offered for callouts. The game blocks addons from using those two
  inside instances, which is the only place callouts appear, so they could never have worked.
  Existing callouts set to Say or Yell have been moved to Instance


V1.63

- Dungeon callouts are now set up from a dropdown instead of one long stacked list. Pick a
  dungeon and you see only its callouts, so the tab stays the same size no matter how many
  dungeons you have set up
- This season's Mythic+ dungeons are in that dropdown already. You no longer have to be standing
  in a dungeon to write callouts for it -- do the lot from anywhere. The list comes from the
  game itself, so it refreshes on its own when the season rotates
- Anywhere else you have been -- raids, older dungeons, scenarios -- is remembered the first time
  you zone in and stays in the dropdown from then on. Raids always worked, there was just no way
  to reach them without being inside one
- The number beside a dungeon is how many callouts it has, so you can see what is set up without
  opening each one. Nothing is saved just by looking at a dungeon; the entry is created when you
  add your first callout to it
- "+ Add Current Dungeon" is still there and now jumps the dropdown to wherever you are standing


V1.62

- Cooldown Manager sound alerts now follow spec and talent changes without a reload. Two things
  were wrong. Talent swaps were not being noticed at all -- the module only watched
  PLAYER_SPECIALIZATION_CHANGED, which does not fire when you change talents inside the same
  spec, so it now also watches TRAIT_CONFIG_UPDATED and PLAYER_PVP_TALENT_UPDATE, the same
  events Blizzard's own Cooldown Manager uses, plus its "cooldown data changed" callback
- And the addon's memory of which spell belongs to which cooldown was never cleared. Those
  lookups are a cache over Blizzard's viewer frames, and the entries for the spec you left stayed
  behind pointing at cooldowns that had since been recycled onto other spells -- so an alert
  could end up reading the wrong spell's state. They are now emptied and rebuilt whenever the
  cooldown set changes
- The Cooldowns settings tab now rebuilds on a spec or talent change too. Groups, assignments and
  the sound alert list are all per-spec, so leaving the panel open across a spec change showed
  the previous spec's setup until something else happened to refresh it
- Kelerts can now fire in combat. Since 12.1 the game hides almost every aura from addons while
  you are in combat -- which is exactly when your alert was supposed to go off -- so an alert on,
  say, a healing cooldown worked in a city and stayed silent in the pull you made it for. The
  addon now hands the spell and the sound to the game up front and lets it play the sound itself,
  so there is nothing left for it to hide. Alerts with a single spell, one sound and no sound
  loop switch to this automatically; nothing to turn on
- The catch, and it is worth knowing: the game plays the sound and tells the addon nothing, so an
  alert delivered this way cannot show its image in combat. The picture still needs an aura the
  addon can see. Sound is the part that now always works
- The lust alert is unchanged -- image and sound both. It watches five debuffs at once, and those
  are among the few the game still lets addons see, so it never had this problem
- The Kelerts tab is now two things. The lust alert stays exactly as it was, image and all. Below
  it is Buff Sounds: a grid of your spec's own buffs, built from your spellbook, so it follows
  every talent and spec change on its own with nothing to keep updated. Click one to give it a
  sound when it lands, when it drops, or both
- Your existing custom Kelerts have moved into that grid, keeping their sounds. Their images are
  gone, because there is no way to keep them -- the game plays these sounds itself and never tells
  the addon it did, which is the same reason they now work in combat at all
- Buffs the grid does not list can still be added by spell ID. Worth knowing for the handful of
  spells whose cast and buff have different IDs


V1.61

- Fixed the per-item "Min" minutes box not saving. It only committed when you pressed Enter, so
  typing a number and clicking away threw it out and the box redrew at the stored value -- which
  looked like the setting reverting to 30 on its own. It now saves when you click away, tab off
  or close the panel, the same as every other box in the addon. Affected every Min box (food,
  flask, oil, augment rune, custom items, self-buff spells and the Coach's Whistle), not just
  food. Escape still discards, and clearing the box and clicking away now leaves the value alone
  rather than reading as 0
- The "Min" boxes now take the mouse wheel: click into one and scroll to nudge it a minute at a
  time, or hold Shift for five. Only while the box has focus, so scrolling the item list with the
  cursor over a box still scrolls the list instead of quietly rewriting a threshold
- Every text box in the settings panel is now drawn in the addon's own style -- square 1px
  borders matching the checkboxes, buttons and sliders, instead of Blizzard's rounded gold search
  border. They light up in the accent colour when focused, and preview it on hover


V1.60

- Reminder buttons now glow, so they catch your eye without being looked at directly. Colour,
  pulse speed and pulse depth are all adjustable, or turn the pulse off for a steady ring. On by
  default; the toggle is under Settings > Misc
- Added a minimap button (left-click settings, right-click unlock frames, drag to move it round
  the edge) and an entry in Blizzard's addon compartment. The minimap button can be hidden
- New installs get a short welcome explaining what the addon does, and an update note listing
  what changed appears once after each new version. /sq notes reopens it

- Kelerts are no longer just the lust alert. The tab is now a list you can add to: pick a
  buff or debuff by spell ID, name it, and it gets its own full-screen image, sound, timing,
  opacity and random-sound pool, exactly as the lust alert always had. The lust alert is still
  there, still watching every lust debuff at once, and cannot be deleted or renamed -- switch it
  off instead. Your existing lust alert settings carry over, in every profile

- New "Show in" settings: pick which content the addon appears in -- open world, each dungeon and
  raid difficulty, Mythic+, timewalking, delves, battlegrounds. Defaults match the old behaviour,
  so nothing changes unless you change it. Mythic+ was previously hidden with no way to turn it
  back on; it is now just another tick box
- The "no food/flask/oil/augment rune in bags" reminders are now one frame that names whichever
  you are short of, rather than up to four banners stacked on top of each other. One position,
  scale and lock between them, with a tick box per category to choose what it mentions. Your
  existing per-category choices carry over, but the frame starts at its default position
- "Lock All" now actually locks everything. It worked from a hand-written list that had fallen
  five frames behind -- the Coach's Whistle, pet, role CC, augment rune and healthstone frames
  were never locked, while the button still reported that everything was

- Augment runes are now tracked like food and flasks: a button to use one when the buff is
  missing, a "no augment rune in bags" reminder, and their own section on the Items tab with a
  drop zone for adding your own. Covers the Midnight and War Within runes out of the box
- Healthstones are now tracked. If you are not carrying one and there is a warlock in the group
  who could make you one, you get a reminder; if there is no warlock, nothing, since it would be
  a reminder to do something you cannot do. Unlike the other bag reminders this one stays up in
  combat, which is when it matters
- Warlocks get a button rather than the reminder, since they are the ones who can fix it. Solo it
  casts Create Healthstone; in a group it casts Create Soulwell so the whole group is covered

- Death Knights are now supported. The class had no entry in the addon at all. You get a reminder
  when an equipped weapon has no runeforge on it, naming which hand is bare. Out in the world the
  button casts Death Gate, since runeforging needs a runeforge; standing in Acherus it becomes
  Runeforging itself
- Class Buffs tab now lists Death Knight runeforging alongside the other class entries, so it can
  be turned off or given its own sound like anything else

- Unlock mode now actually unlocks everything. A frame you had locked would show its green
  preview tint and then refuse to be dragged, because the preview code was still honouring the
  per-frame lock it exists to override. Locked frames can now be repositioned without unlocking
  them first
- Every movable frame now gets the green preview tint. The Coach's Whistle, pet and healer/tank CC
  frames never had one, because each frame's overlay was written out by hand and those three had
  been missed. They are now generated from one list, so a new frame cannot be forgotten
- The markers and pull/ready frames can now be dragged. Their buttons cover almost the whole
  frame, so trying to move them fired a ready check, started a pull, or placed a raid marker
  instead. Their buttons are click-through while frames are unlocked
- The dungeon callouts frame can now be dragged from anywhere on it, not only its title bar
- Removed the small tab above the buttons frame. That frame is now dragged directly like every
  other frame, while frames are unlocked, so there is no permanent scrap of UI on screen
- Settings panel: fixed dropdowns overlapping the label of the option below them, long
  descriptions running into the next setting, and section headings sitting flush against the row
  above

- Settings are now backfilled recursively, so a new option nested inside an existing group
  reaches everyone rather than only new installs. Previously only top-level settings were filled
  in automatically and each nested group needed its own hand-written merge, which is how two
  separate one-off fixes for the lust alert came to be needed. One-time repairs to saved data are
  now a numbered, ordered list rather than a boolean flag per fix
- "Enable Bag Reminders" did nothing. Turning the master toggle off left the reminder showing for
  as long as any single category underneath it was still ticked
- Internal: each reminder used to decide for itself whether it should be on screen, which meant
  the same class, spec, group and content-type checks written out ten times over, free to drift
  apart -- and they had. Every reminder now declares which of those checks apply to it and they
  are evaluated in one place. The bag reminder bug above is what that turned up
- Internal: the button-building code was one 900-line function covering class buffs, consumables,
  layout and sounds together. It is now four, which is why several bugs in it this release took as
  long to find as they did

- Class buffs now show the "Min:" minimum-remaining-duration box for every buff, not only for
  self buffs, tank buffs and weapon imbues. The threshold was always being applied to group buffs
  like Fortitude and Arcane Intellect -- defaulting to 30 minutes -- there was simply no way to
  see or change it. Set it to 0 to only be prompted when the buff is missing entirely. Buffs with
  no duration, such as Paladin auras and Lightning Shield, are unaffected

- Performance: the addon used to walk every bag slot repeatedly on every update. Rebuilding the
  buttons is driven by UNIT_AURA, which fires for every member of your group on every aura change,
  and each pass did several full six-bag walks plus another complete walk for every button it
  built. The "no food/flask/oil in bags" checks were worse again -- a full bag walk nested inside a
  loop over every configured consumable. Bag contents are now scanned once when the bags actually
  change, and every check is a table lookup. In a raid this was running more or less continuously
- Consumable buttons now appear in the order the items are configured rather than the order they
  happen to sit in your bags, so they stop moving around when you rearrange your bags

- Cooldown Manager sounds: the "when available" alert never fired in combat. It would arrive late,
  when combat ended, or get flushed early by some unrelated spell's alert. Several causes stacked
  on top of each other:
    * Nothing drove the sound pass on a clock. It ran only from buff-state-change hooks, and a
      cooldown finishing is not a state change -- no event fires when a timer merely runs out. It
      now polls on its own ticker
    * C_Spell.GetSpellCooldown hands an addon secret startTime/duration in combat, so the addon
      cannot work out whether a spell is ready; comparing those values throws. It now reads the
      answer Blizzard already computed and cached on its own Cooldown Manager item frame
    * That cached value is itself secret while a cooldown is running, and a plain false when the
      spell is ready -- so a secret value *is* the "still on cooldown" signal, and the transition
      out of it is the moment the spell becomes available. Treating secret as "cannot tell" threw
      away the exact signal the alert needed
    * A spell can appear in two Cooldown Manager viewers at once -- one tracking its cooldown and
      one tracking the buff it applies -- and only the first carries cooldown state. The buff copy
      was being read for some spells, where every cooldown field is empty
- Cooldown Manager sounds: alerts were keyed by Blizzard's cooldown ID, which is not stable -- the
  same spell gets different IDs between categories and between game builds. Alerts saved under an
  older ID silently stopped firing, and adding them again created a duplicate rather than fixing
  the original; one profile had the same spell stored three times over. Alerts are now keyed by
  spell ID, and existing ones are migrated across and de-duplicated on load
- Cooldown Manager sounds: "Active" now also fires for a buff you place on your current target,
  not only on yourself. A buff on a party member who is neither you nor your target still cannot
  be seen -- Blizzard's Cooldown Manager only tracks player and target, so there is nothing to
  read
- Cooldown Manager sounds: a spell that appears in two of Blizzard's viewers at once -- once for
  its cooldown and once for the buff it applies, as Blessing of Freedom does -- was listed twice
  in the spell picker. Both entries edited the same alerts while each offered only half the
  triggers, so which options you saw depended on which of the two icons you clicked. Each spell is
  now listed once, with the triggers merged from all of its entries
- Cooldown Manager sounds: the alert trigger list is now taken from Blizzard's own per-spell list
  rather than assumed from the category. "Active" is no longer offered on spells that apply no
  buff and could never fire it, and is relabelled "Active (buff up)" -- it means the buff is up,
  not that the ability is ready
- Cooldown Manager sounds: spells with alerts configured are now marked in the picker with a
  border and a speaker badge, and spells without any are dimmed, so the list can be read without
  clicking through every icon

- Cooldown Manager sounds: alerts on cooldowns not in Blizzard's Cooldown Manager, and the
  "buff removed" alert, could go quiet in combat for the same secret-value reasons. Each alert
  type is now gated only on the data it actually depends on, rather than one blanket check that
  silenced everything
- /sq cdm now reports combat state, which alert delivery path each configured sound uses, and
  whether the underlying cooldown data is readable -- the whole chain above was diagnosed with it

- Encounter timeline: the pull countdown now also appears on Blizzard's encounter timeline,
  alongside boss abilities. It is driven by the game's countdown event rather than by our own
  Pull button, so a pull started by anyone in the group shows up, not just your own. Toggle on
  the Raid Tools tab; /sq timeline reports whether the timeline is available on your client and
  fires a test event. Blizzard's timeline has to be switched on for this to show anything --
  Options > Gameplay > Combat > Combat Warnings, 'Enable Boss Warnings' then 'Boss Ability
  Timeline' -- and /sq timeline now names whichever of those two is off rather than just
  reporting that the feature is disabled
- Encounter timeline: investigated building BigWigs-style per-ability boss sounds directly into
  the addon, and it cannot be done. Of the data the timeline gives an addon about an incoming
  ability, only its ID, source and duration are readable — the spell ID, name, icon and severity
  are secret values, which can be displayed but not compared. So an addon can draw a bar for an
  incoming ability but cannot find out which ability it is. BigWigs works around this by
  identifying abilities from their duration rounded to the nearest second, against a hand-built
  table per boss and per difficulty, which is a per-patch maintenance job for every boss in the
  game. Not something worth taking on when BigWigs already does it well. Recorded in NOTES.md
  so it does not get attempted again

- Profiles: frame positions for the flask, oil, healer CC and dungeon callout frames were
  never carried between profiles — PROFILE_POSITION_KEYS was a hand-maintained list that had
  drifted out of sync with the frames that actually exist, so those four were neither saved to
  nor restored from a profile and silently kept the previous profile's anchor on a switch.
  The list is now derived from POSITION_PAIRS so it cannot drift again
- Profiles: five separate places each hand-listed which frame positions to reload after a
  profile change and every list was missing a different subset; all now call one
  BH:LoadAllFramePositions()
- Profiles: frame scales are per-profile settings but were only ever applied at login, never on
  a profile switch, so switching profiles kept the old profile's scales until the next reload
- M+ Death Tally: the scale setting was saved correctly but never applied at login, so the
  tally always came back at 100% after a reload
- Paladin auras: picking Concentration Aura left both aura buttons on screen, including one for
  the aura you had just activated. The show/hide decision was a single all-or-nothing gate that
  for Holy only tripped on Devotion — the Devotion exception is deliberate (you want it
  available for Aura Mastery even when another paladin has it covered) but it also kept
  offering every other aura. An aura you currently have active is now never offered
- Clicks on the reminder buttons were sometimes swallowed, needing three or four attempts.
  Two causes: (1) UpdateButtons unconditionally tears down every button and is driven by
  UNIT_AURA, which fires for every group member on every aura change, so a rebuild landing
  between mouse-down and mouse-up ate the click — rebuilds are now deferred while the cursor is
  over a button; (2) the buttons registered both "AnyDown" and "AnyUp", firing the secure
  action twice per click with the second attempt landing inside the GCD of the first — all
  secure buttons now use a single click edge chosen from the client's ActionButtonUseKeyDown
  setting, matching Blizzard's own action buttons
- The same double-fire affected the dungeon callout buttons, which were sending their chat
  message twice, and the raid target markers, whose "toggle" action was set and then
  immediately cleared by the second fire
- Talent-granted and talent-overridden spells were not detected: plain IsSpellKnown() returns
  false for both, so a reminder could silently never fire for a given build. All 16 call sites
  now go through a helper that falls through C_SpellBook.IsSpellKnown, IsPlayerSpell,
  IsSpellKnownOrOverridesKnown and IsSpellKnown
- The reagent bag was never scanned, so consumables kept there were invisible to the addon
- Opening the options panel leaked frames: the item, class buff and custom sound lists
  destroyed and rebuilt their rows every refresh, and WoW frames are never garbage collected.
  Rows are now cached and reused, so after the first build a refresh allocates nothing
- Secret value handling is now centralised in Squizzumables_Secrets.lua, built on the client's
  real predicates (issecretvalue, issecrettable, hasanysecretvalues, C_Secrets). The main file
  previously used pcall for this while the Cooldown Manager module used inline issecretvalue
  checks; pcall works but allocates a closure at every call site and has to be repeated at
  every downstream comparison, which is how the v1.58 aura crash got through. Checking once,
  where the value is read, means the result is safe to use freely afterwards
- The per-button buff countdown was rebuilding a closure on every button on every rendered
